# 고정 데스크톱 패널

## 동작과 저장

- 대시보드와 메뉴 막대의 `고정 패널` 버튼 또는 설정의 `패널 표시`로 연다. 이미 열려 있으면 같은 창을 앞으로 가져오며 새 창을 만들지 않는다.
- 기본은 일반 창 높이의 `NSPanel`이다. 다른 앱으로 전환해도 숨기지 않으며, `항상 위`를 켠 경우에만 floating 높이를 사용한다. 자동 복원은 앱을 활성화하지 않고, 사용자가 직접 열었을 때만 창에 포커스를 준다.
- 목록과 2열 배터리 표시를 제공한다. 별명은 줄바꿈하며 수집 시각·연결 상태·재로그인·오래된 값이 표시된다. 남은 값의 정밀도와 상태 해석은 위젯의 표시 모델을 사용한다. 창이 작으면 스크롤한다.
- 최대 6개 계정을 고르고 순서를 바꿀 수 있다. 기본은 메뉴 막대의 고정 ID를 따르며 고정 ID가 없으면 표시 계정 중 처음 6개를 제안한다. 사용자가 패널에서 적용한 뒤에는 패널의 선택을 독립 저장한다. 명시적 빈 선택, 숨긴 계정, 찾을 수 없는 ID도 임의로 바꾸거나 잘라내지 않는다.
- 각 카드에서 정확한 계정 상세로, 대시보드 버튼에서는 전체 화면으로 이동한다. 계정 URL과 대시보드 URL은 허용한 형태만 받는다.
- 위치·크기·표시 여부·선택 ID는 기존 schema 1 설정의 선택적 `panel` 필드에 저장한다. 기존 파일에 이 필드가 없으면 패널은 꺼져 있다. 목록/배터리와 항상 위 설정은 기존 필드를 유지한다. 잘못된 용량·중복·비정상 좌표는 저장을 거부하고 기존 파일을 보존한다.
- 창 이동은 200ms 동안 합쳐 저장하고, 크기 조절 종료·닫기·앱 종료에는 최종 프레임을 저장한다. 패널을 직접 닫으면 표시를 끈다. 앱 종료는 표시 설정을 유지해 다음 실행에서 복원한다.
- 창을 복원하거나 화면 구성이 바뀌면 현재 디스플레이의 사용 가능한 영역 안으로 크기와 위치를 조정한다. 저장된 영역과 가장 많이 겹치는 디스플레이를 우선하며, 사라진 디스플레이에 있던 창은 사용 가능한 화면으로 옮긴다.

## 수집과 데이터

- 패널은 대시보드와 같은 `DesktopModel.snapshot`을 관찰한다. 별도 collector, 네트워크 클라이언트 또는 수집 타이머를 생성하지 않는다. 수동 갱신도 기존 단일 coordinator에 선택 ID를 전달한다.
- 30초의 SwiftUI `TimelineView`는 마지막 값의 오래됨 표시만 갱신하며 수집 성공이나 새 `fetchedAt`을 만들지 않는다. 정상 자동 수집 주기는 기존 coordinator의 60초다.
- 앱 내부 언어·테마·카드 스타일 변경은 열린 패널에 반영된다. WidgetKit 확장으로 이 설정을 전달하는 작업과는 별개다.

## 검증

```sh
bash macos/Scripts/test-host-state.sh
bash macos/Scripts/test-panel.sh
bash macos/Scripts/test-widgets.sh
```

- 호스트 검사: 기존 설정 호환, 켜짐/스타일/순서/크기/위치 저장과 재열기, 명시적 빈 선택, 7개·중복·NaN 프레임 거부, 대시보드와 기존 계정 링크 검증.
- `test-panel.sh`: 실제 AppKit 컨트롤러와 새 설정 파일로 일반/floating 높이, 비활성화 시 숨김 없음, 재사용, 창 이동·크기 저장, 닫기·새 컨트롤러 복원, 활성화 상태 불변, 앱 종료와 패널 닫기 구분을 검증한다. 모니터 제거·큰 창·최소 크기 복원 계산도 검사한다. 내용 View는 빈 테스트 View이며 아래 실제 앱 검증과 구분한다.
- 실제 Debug 앱의 격리된 12계정 QA 저장소에서 두 Claude·두 Codex 선택, 순서 변경, 6개 상한, 빈 선택 적용과 종료/재실행, 배터리/목록, 창 크기 변경, 항상 위 켜기/끄기, 패널만 닫기, 대시보드/정확한 Codex 계정 상세 이동을 확인했다.
- 실제 앱 종료 후 표시 여부·504×642 프레임·순서가 보존됐으며, 한국어/영어와 밝게/어둡게 전환이 열린 패널에 반영됐다. 선택 순서 목록과 계정 목록의 ID 충돌 및 앱 종료 시 패널이 꺼지던 회귀를 이 과정에서 수정했다. 순서 변경 버튼은 접근성 트리에서 개별 조작해 확인했다.
- 별도 QA 복사본에서 실제 코어 저장 API로 합성 사용량을 발행했다. 실제 패널의 목록과 배터리에 50%·83.6%·7%, 로그인 필요, 연결 해제의 빈 값이 저장된 snapshot과 일치했다. 자동 수집은 꺼 두었고 실제 제공자 로그인이나 Keychain 항목은 사용하지 않았다.
- Debug arm64와 Release arm64/x86_64 앱·위젯 빌드 및 기존 위젯 producer/consumer 회귀 검사를 실행한다. 자세한 해당 실행 결과는 [구현 상태](implementation-status.ko.md)를 참조한다. 로그와 QA 저장소는 Git 제외 경로 `artifacts/macos-20260917-panel/`, 독립 AppKit 검사는 `artifacts/macos-panel-probes/`에 보존한다.

## 남은 검증

- 실제 제공자 계정에서 60초 수집 결과가 계속 반영되는 장기 계측, 패널 표시 전후 네트워크·CPU·메모리·전력 비교.
- 실제 모니터 분리·재연결, 여러 Spaces·전체 화면, VoiceOver 음성 및 접근성 환경의 실제 사용. 복원 계산과 접근성 트리 검사가 이 전체 범위를 입증하지는 않는다.
- 최소 크기의 실제 UI 검사는 컴퓨터 조작 도구의 창 경계 드래그 오류로 끝내지 못했다. 실제 504×642 크기 변경과 표시, 최소 크기 복원 계산은 확인했다.
- 실제 Developer ID 서명·공증과 업데이트 전후 설정 복원. 현재 빌드는 `CODE_SIGNING_ALLOWED=NO`다.
