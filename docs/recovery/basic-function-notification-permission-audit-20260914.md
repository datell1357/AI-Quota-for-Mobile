# 기본 기능·알림·권한 점검 (2026-09-14)

대상: `recovery/production-53`의 복구 작업 트리, Android 1.2.0(54) debug.
프로덕션 53에 배포된 변경이 아니다. AAB 생성·업로드는 업로드 키 교체 완료까지 보류한다.

## 판단

새 로그인 이후 사용량을 표시하는 공통 경로는 유지돼 있다. 그러나 모든 제공자에 대해
초기 로그인·업그레이드·인증 만료·수일간 유지가 모두 안전하다고 판단할 근거는 부족하다.
특히 OpenCode·GLM은 실제 계정 없이 파서·상태 전이·43 배포 코드와 비교한 결과다.

다음 항목은 배포 전에 별도 대응이 필요한 미해결 사항이다.

1. **43에서 계정 이전 후 자동 갱신 중단 가능:** 기존 OpenCode·GLM 연결은 새 계정에
   `REAUTH_REQUIRED`로 이전된다. 인증정보가 남아 있어도 자동 갱신 대상에서 제외된다.
   Claude·Codex 전용 `LegacySessionCarryOver`는 이 두 제공자를 처리하지 않는다.
   기존 자격 증명을 검증한 뒤 계정을 인증 상태로 승계하는 경로가 필요하다.
2. **인증 오류 후 재로그인 필요:** exact 갱신 서비스에서 대화형 인증이 필요하다고
   판정하면 `requireReauthentication`으로 전환한다. GLM 웹 복구까지 실패하면 이후
   갱신이 중단된다. 일시적 오류와 실제 만료를 구분하는 제한된 재검증 정책이 필요하다.
   OpenCode 일반 수집 오류는 재시도되므로 모든 HTTP 오류가 이 상태가 되는 것은 아니다.
3. **WebView 수집의 비정상 종료 복구 부족:** `ServiceCollectorWebViewClient`,
   `GlmIsolatedWebSessionService.GlmWebClient`, `BackgroundCollectorWebViewClient`에는
   `onRenderProcessGone` 처리가 없다. 렌더러가 종료되는 상황의 안전한 정리와 실패 전달,
   이후 재시도는 추가 검증·보완 대상이다. 실제 기기에서 해당 종료를 재현한 것은 아니다.
   `WebLoginActivity.LoginWebViewClient`에는 이미 처리가 있으므로 모든 WebView가
   처리하지 않는다고 일반화하지 않는다.

상세 근거: [OpenCode·GLM 43 비교](opencode-glm-v43-comparison-20260914.md).
이번 점검에서 인증 정책을 임의로 완화하거나 기존 데이터를 삭제하지 않았다.

## 이번에 확인하고 수정한 문제

### 매분 기존 알림을 다시 게시

앞선 수정은 사용자가 지운 알림의 부활과 과거 리셋 시간의 반복 감지를 막았다.
추가로, 화면에 남은 알림은 snapshot version이 바뀔 때마다 alias updater가 다시
게시하는 경로가 남아 있었다. 계정 이름이 같다면 Android 알림을 재게시하지 않고
저장된 version 등 메타데이터와 리셋 버튼 PendingIntent만 갱신하도록 수정했다.
실제 이름 변경으로 재게시할 때도 기존 알림 시각을 유지한다.

`RepeatedPostedNotificationTest`에서 리셋·임계값 알림을 함께 남겨 두고 60번 연속
version을 증가시켜 재게시 0회를 검증한다. 삭제한 알림의 부활 방지와 살아 있는
알림만 이름 변경하는 기존 테스트도 유지했다. 이 문제의 테스트는 수정 전 실패했다.
실제 임계값을 새로 넘거나 새로운 리셋 주기가 도래하면 정상적인 새 알림은 발생한다.

### 권한 요청 누락과 차단 상태 오표시

- 제공자 상세의 리셋·사용량 알림을 켤 때 공통 권한 요청을 거치도록 연결했다.
- 제공자 알림 권한 허용과 라이브 갱신 활성화를 구분했다.
- Android 13 이상에서 최초 런타임 요청 후 이미 거절한 상태는 설정 화면으로 안내한다.
- Android 12 이하도 시스템의 앱 전체 알림 차단을 실제로 확인한다.
- 리셋·사용량·상태 알림 중 개별 채널이 차단되면 해당 채널 설정으로 안내한다.
- 상태 알림 채널이 꺼졌다면 화면에서 사용 가능한 것으로 표시하지 않는다.
- 라이브 갱신 활성화 요청으로 설정을 열었다면 돌아왔을 때 권한을 재검사하고 이어서 활성화한다.

알림은 POST_NOTIFICATIONS, 절전 예외는 시스템 설정을 통해 요청한다.
배터리 최적화 예외는 권장 설정으로 유지하며, 예외가 없다는 이유만으로 로그인 때마다
이미 설정한 라이브 갱신 안내를 다시 열지 않는 기존 수정도 점검 대상에 포함했다.
